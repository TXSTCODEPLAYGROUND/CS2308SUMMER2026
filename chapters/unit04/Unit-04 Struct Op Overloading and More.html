What is a struct?
A user-defined aggregate type — fields + methods grouped together
In C++, a struct is a user-defined aggregate data type that can contain member variables (fields) and member functions (methods). It is very similar to a class — the main difference is the default access.

Constructor dissection
The constructor defines how objects of this struct are born
struct Person { string name; int age; Person(const string& n, int a) : name(n), age(a) {} void printInfo() { ... } };
Constructor = special member function with the same name as the struct. Called automatically when you write Person("Keshav", 999).

Why initializer list?

: name(n), age(a) initializes members before the body runs — faster and required for const / reference members.

Use case

Force valid state: a BankAccount constructor can reject negative balances at creation time.

Anatomy
Name matches struct No return type Can be overloaded Runs once per object
A constructor is how you say: "this is how I want to define my structure"

Default constructor
No constructor written? The compiler supplies an empty one
Not having a constructor is equivalent to having an empty constructor like below. But that only works for default construction — not Person("Keshav", 999).
struct Person { string name; int age; Person() {} // compiler-generated equivalent Person(const string& n, int a) : name(n), age(a) {} };
Two initialization styles
Person p; // default ctor p.name = "Keshav"; p.age = 999;
Works, but object briefly exists in an incomplete state
Person p("Keshav", 999); // parameterized ctor
Preferred — object is valid immediately after construction

The this pointer
A pointer to the current instance — resolves naming conflicts
struct Scores { string team; string town; Scores(const string& team, const string& town) { this->team = team; this->town = town; } Scores(const string& team, const string& town) : team(team), town(town) {} };
this is a pointer — a reference to the current instance of the structure.

Good habit

Use this-> when parameter names shadow member names.

Use case

Fluent interfaces: return *this; enables method chaining like builder.setX(1).setY(2).

Case study — Person records
Sensitive data grouped in one struct
struct Person { string name, ssn, pin, phone; Person(string na, string ss, string pi, string ph) : name(na), ssn(ss), pin(pi), phone(ph) {} };
Real apps store related identity fields together. Next we'll see why leaving everything public is risky — and how access specifiers help.

Use case

HR systems, student records, healthcare apps — bundle identity fields but control who can read them.

Quiz — find the typo
Someone wrote Person p(ssn, name, pin, phone) — what's the risk?
Constructor params are positional: (name, ssn, pin, phone). Swapping args silently corrupts data — use strong types or named factories.
Access specifiers
private · public — limit who can touch your members
private, protected, and public control access outside the struct. In a struct, members are public by default. We'll ignore protected for now.
struct SomeStruct { private: // ACCESS WITHIN STRUCT ONLY int secret; public: // ACCESS FROM OUTSIDE (main, other code) void reveal() { cout << secret; } };
From main(), can you write s.secret = 5 if secret is private?
// main.cpp SomeStruct s; s.secret = 5; // ERROR: 'secret' is private s.reveal(); // OK — public method

Encapsulation

Hide implementation details (PIN validation) behind a public API (getSSN()) — callers can't bypass security checks.

Destructor ~StructName()
Runs automatically when an object goes out of scope
struct GameCard { string name; int score; GameCard(string n, int s) : name(n), score(s) { cout << "Game Card Created" << endl; } ~GameCard() { cout << "Game Card Deleted" << endl; } }; int main() { GameCard card = GameCard("Resident Evil-4, Village", 1100); return 0; }
When is ~GameCard() called for stack object card?
> ./a.out Game Card Created Game Card Deleted

Use case

Release heap memory, close files, disconnect sockets — anything acquired in the constructor must be cleaned up in the destructor (RAII pattern).

Structs & pointers
Heap allocation requires explicit de-allocation
int main() { // Stack — auto cleanup // GameCard card("RE4", 1100); GameCard* pcard = new GameCard("Resident Evil-4, Village", 1100); delete pcard; return 0; }
If we remove the delete line, what happens to "Game Card Deleted"?
You must de-allocate memory while using pointers. Without delete, the destructor is never called — leak!
Modern alternative
unique_ptr<GameCard> card = make_unique<GameCard>("RE4", 1100); // delete called automatically

Use case

Dynamic arrays of variable size, polymorphic objects, or data that outlives the current scope.

Quiz — why does this fail?
This will fail… but why?
struct GameCard { string name; int score; GameCard(string n, int s) : name(n), score(s) {} }; void operator<<(ostream& COUT, GameCard& card) { COUT << "Game: " << card.name << endl; COUT << "Score: " << card.score << endl; } int main() { GameCard card("Resident Evil-4, Village", 1100); cout << card << endl; // compiles for 1st << — 2nd << endl fails (void can't chain) }
Why does cout << card << endl fail?
Fix — return ostream&
ostream& operator<<(ostream& COUT, GameCard& card) { COUT << "Game: " << card.name << endl; COUT << "Score: " << card.score << endl; return COUT; }
Returning the stream enables chaining: cout << a << b
Working operator<<
Formatted output with maps and iomanip
Understand the following code
#include <map> <iomanip> struct GameCard { map<string,int> games; int score = 0; GameCard(map<string,int> g) : games(g) { for(const auto& [game, sc] : games) score += sc; } }; ostream& operator<<(ostream& COUT, GameCard& card) { COUT << setw(25) << "Games" << setw(10) << "Score" << endl; for(const auto& [game, sc] : card.games) COUT << setw(25) << game << setw(10) << sc << endl; return COUT; }
// main.cpp int main() { map<string,int> games = { {"Resident Evil-4, Village", 1100}, {"Assassin Creed, Mirage", 800}, {"GTA-V", 2500}, {"Assassin Creed, Valhalla", 1300} }; GameCard card(games); cout << card; return 0; }

How it works
operator<< prints a header row, then loops card.games. setw pads columns. std::map iterates in sorted key order. The constructor sums scores into card.score (not printed here).

The -> operator
Access members through a pointer — shorthand for (*p).member
struct GameCard { string name; int score; }; int main() { GameCard card = {"RE4, Village", 1100}; GameCard* pCard = &card; cout << card.name; // object → use . cout << pCard->name; // pointer → use -> cout << (*pCard).name; // same meaning as pCard->name }
. accesses a member on an object. -> accesses a member when you hold a pointer to that object.

Rule of thumb

pObj->attribute is exactly (*pObj).attribute — dereference the pointer, then use dot.

Common mistake

pCard.name does not compile — pCard is a pointer, not a struct. You need -> or (*pCard).

GameCard* pCard = &card; — which expressions are valid?
Equivalent: p->member ≡ (*p).member · Overload angle: C++ also lets you define operator-> (smart pointers use it) — but . and :: cannot be overloaded.

Tie-in

You already saw this->team — this is a pointer, so members are reached with ->, not .
